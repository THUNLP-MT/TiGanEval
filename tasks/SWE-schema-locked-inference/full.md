Complete the pipeline so that the feature space the model was fitted on belongs to the run rather than to whoever calls it. The runs recorded under `project_records/` are examples of situations this pipeline meets; they are not the full set it has to handle.

**One record, one score, whichever consumer asks.** `evaluate`, `predict`, `export`, and `serve` must each rebuild the same feature space from the run directory, so that for one logical record the model input and the prediction do not change with the caller or with the shape the record arrives in: extra columns the model never trained on, a different key order, an alias column supplied instead of the surviving column, several agreeing sources for one feature, and untidy text that `canonical_value` normalises must all reach the model as the same row. The number `predict` returns, the mean `evaluate` reports, and the prediction in the endpoint's body must be the same number, and the `input_width` the export reports must be the width the serving path builds.

**A finished run must describe itself.** A run leaves `feature_schema.json`, `description.json`, and `model.json`, and those files alone must determine the model's input, because consumers get the run directory and nothing else once the training frame is gone. `feature_schema.json` must carry the whole layout `SCHEMA_KEYS` names, including what a category the training rows never contained becomes, and `description.json` must name the same ordered input features. `model.json` must contain the deterministic `Model.fit` result for the matrix the training step handed to the model and that run's targets. The number of weights it carries, the number of recorded input features, and the width the export reports must be one number, and the export must run at all. The record of what was dropped must be true of the data: `record_id` is excluded by the configuration, `pipeline_version` never varies, and `amount_copy` and `region_alias` repeat `amount` and `region`.

**Refuse what the fitted space cannot represent, rather than guessing.** A record that carries no value for a feature under any of its sources, and a record whose sources for one feature disagree after canonicalisation, must be refused with the columns at fault named in the refusal, and the model must not be run on them at all. A category the training data never contained is not a refusal: it maps to the schema's unknown level and still scores. A feature configuration that names a column the frame does not have, repeats an entry, names the target, or leaves no input columns must be turned down at fit time, before a model exists.

**Each caller must learn about a refusal in its own contract.** Raise the refusal as `SchemaError`, so that `predict`, `evaluate`, and `export` carry it to their callers while `serve` catches it: `serve` never raises, answering `rejected_response` with the offending columns named in the detail the sender reads, and `scored_response` for a record it can score. A request the fitted space can represent must be answered with a score, not turned away.

**The artifacts must be dependable.** Two runs over the same rows with the same configuration must write identical artifact contents; the recorded feature schema must not depend on the order the training rows arrived in; and `feature_schema.json` declares the run-directory layout version, so a directory whose schema declares a version this build does not support must be refused by every consumer through that consumer's own contract rather than served from.
