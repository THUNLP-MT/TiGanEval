Finish `ingest/recover.py` so that one unreadable column costs us that column and nothing more, while everything downstream still knows which parts of a published record came from the provider and which are ours. `ingest/protocol.py`, `ingest/schema.py` and `ingest/consumer.py` stay as they are; `ingest/support.py` is yours. `recover(payload, record)` returns a reading carrying `value`, `is_complete`, `structured_fields`, `failed_fields`, `errors`, and a `refine(patch)` method, which is the surface `consumer.py` is built against. The recorded drops under `project_records/` are four nights this job has had, not the list of situations the finished reading has to handle.

The two column sets partition the columns the file supplies. A column belongs to `structured_fields` exactly when the payload carried a key for it and that key's content read cleanly against the contract; every other supplied column belongs to `failed_fields`, whether the payload carried no key for it at all or carried something that would not read. A column falling back to the value declared in `ingest/schema.py` is a gap, not provider data: the fallback is ours. The two sets are disjoint, their union is exactly the columns the file supplies, and a column the ingest computes for itself appears in neither. `is_complete` is true exactly when there are no gaps.

A record is published whole or not at all. `value` is produced when every gap has a declared fallback, and is `None` when any column without one is missing or unreadable, so a record that would carry an empty required column is withheld and the reading carries its problems instead. Every column of a produced record holds either the value the payload's content read as or exactly the fallback the contract declares for it — never `None`, never a placeholder of the right shape — and a column the ingest computes for itself holds what the contract computes from those values, because the billing table is keyed on it.

Recovering the record must not change the diagnosis. `describe_errors(reading.errors)` must equal `describe_errors` of the errors `protocol.structure` raises for the same payload: the same messages at the same paths, including nested paths such as `$.address.postcode`, element indices such as `$.lines[2].quantity`, a missing-field line for every key the payload did not carry, and the unknown-key line for a key the contract does not declare. Support matches those lines against old incidents, so a truncated path or a line that never appears sends the analyst to the wrong place.

A nested block recovers in part; a list does not. When part of a nested block reads, the parent keeps that partly-read block as its value and still counts the column as a gap, because part of what we publish under it is ours. When no value can be made for the block at all, it is an ordinary gap and falls back to the declared block. A list column is atomic: it equals the whole strictly-read list, element for element and in order, or it is a gap and falls back to its declared value. Nothing published may be a list the file did not carry in that exact shape.

Support's corrections fold into a reading that already exists. `refine(patch)` returns a new reading in which every column already in `structured_fields` keeps its exact value and stays there, only columns in `failed_fields` are attempted again from the patch, a patch key naming a column that already read is ignored, and the reading it was called on is left as it was. The end state is the same whichever way support sends the same corrections: all of them in one patch, half in one patch and half in the next, or a patch that repeats columns that had already read.
