Finish the console's session bundles so that a file the desk writes is a truthful record of the session it came from, and a file the desk opens is admitted before execution and runs under the receiving console's own numbering and the caller's controls. The sessions under `project_records/` are examples of what the desk does with these files, not an exhaustive list of the situations the finished recorder and replay have to handle.

Every recorded entry carries exactly what its own cell put on screen, split by kind through the frozen `split_outputs`: explicit writes to stdout in `stdout`, writes to stderr in `stderr`, and the value the cell's last expression evaluated to in `execute_result` as `text/plain`, absent when the cell's last statement is not an expression or evaluated to None. The console's store keeps everything ever printed under an execution counter, because `Out[n]` is served from it, and a quiet cell shares its counter with the numbered cell that follows it. Even with that shared counter, neither the quiet cell's output nor anything older belongs to the numbered cell's entry. Recording observes the console without consuming or rewriting that store or changing any cell's result, so a later `Out[n]` lookup behaves exactly as it would without the recorder.

Every pattern handed to `start` is gone from every string in the recorded events — the code, what the cell printed, what it wrote to stderr, the value it came back with, the message a failing cell raised and every line of its traceback — each occurrence standing as the console's own `REDACTION_MARKER`, while every other event field has the value an ordinary recording would have written. Metadata is the bundle's structural header and is not redacted, even when a pattern equals one of its literal values; it must keep the format valid. Patterns belong only to the recording whose `start` received them, so a later recording started with no patterns is an ordinary unfiltered record.

A recording covers exactly the numbered cells run between `start` and `stop`, each once, in order, with `seq` running from 1, including a cell that raised; nothing the analyst ran before the start or after the stop is in it, and neither are the quiet cells the front end runs for its own panels. Both hooks come off at `stop`, so a console that is no longer being recorded is not still feeding a recorder. One console is recorded into one file at a time, however many recorders the app has built against it: being recorded is a state of the console, which is where its hooks are, and not a state of the recorder the analyst happened to press. A `start` that is refused — because this console is already feeding a recorder, whichever recorder was asked and whether or not it is the one holding the session, or because the target is already a bundle and nothing said to replace it — is decided before anything is attached or written, so it leaves the recorder, the console's hooks, what `status()` reports and the file already on disk exactly as they were; it raises rather than returning, which is how the desktop app knows to put the refusal in front of the analyst.

A bundle is a document another machine produced, so it is admitted whole or not at all: `load_bundle` itself reads the file and checks it against `schema_errors`, so the refusal has already happened for a caller that only wanted to look at the file, and a replay inherits it because it goes through the same door. A file with any fault runs no cells at all and is refused with `BundleRejected` carrying exactly the codes the frozen reference returned for it; a file with no faults loads and runs. Loading a file is never the thing that executes it. A replay that ran the sound part of a broken file and stopped leaves a console that looks like a finished analysis, and the number somebody reads off it is published without anything in the transcript saying where it came from.

A replay runs each admitted event's recorded source exactly once in the console it is handed, so the analysis can rebuild its values there, but the execution numbers in the file belong to the session the file came from and are read, never written back into the receiving console. That console keeps its own numbering, advancing once per replayed cell when the caller asked for history and not at all when it did not. With `stop_on_error` the replay stops at the first cell that fails and runs none of the cells after it; without it the replay runs the file to the end. Its `ReplayReport` lists exactly those event sequence numbers once and names the event where it stopped, or no stopping event when it ran through.

`bundle/recorder.py` and `bundle/replay.py` are the files to change. `bundle/protocol.py` ships in the console release. You can inspect the project, replay the recorded sessions and run your own experiments before you deliver.
