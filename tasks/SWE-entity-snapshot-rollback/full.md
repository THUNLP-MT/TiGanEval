Complete the level editor's checkpoint feature so a designer can take a checkpoint, keep working, and get exactly the level she checkpointed back. The five sessions recorded under `project_records/` are examples of what designers do, not an exhaustive list of the situations the finished feature has to handle.

A checkpoint is a value, not a view of the level. Nothing a designer does after taking one may change what it holds, and nothing it holds may end up inside the level, so `capture_entity` and `capture_scene` copy every trait payload and every link payload rather than handing back the live stores `World.trait` and `World.edges` return, and `restore_entity` and `restore_scene` put copies into the world rather than the file's own objects. Reverting to one checkpoint twice, with edits in between, gives the same level both times, and that level is the one the checkpoint holds: after a revert `world_digest(world)` equals `digest_of_checkpoint(file)`. No two props end up sharing one store.

A revert removes as well as restores. Afterwards a prop carries exactly the trait keys the checkpoint records for it and no others, so a tag added during a bad pass is gone and a trait removed during it is back; every recorded payload compares equal to what was recorded; and a key the registry declares as a tag comes back as a tag rather than as an empty payload. This holds for `restore_entity` on one prop and for `restore_scene` across the level.

A revert of the whole level restores which props exist before it restores how they hang together. A prop destroyed after the checkpoint was taken comes back at the id it had, which means `World.reserve` at its recorded slot and generation, because `World.create` only ever moves a slot's generation forward. A prop created after the checkpoint was taken is gone afterwards. Every link the checkpoint records exists exactly once and resolves to the prop that held that id when the checkpoint was taken; a link made during the bad pass, including one onto a prop that took over a freed slot, is gone. Slot 0 is the editor's own session entity: it is not in a checkpoint and a revert leaves it alone, so the designer keeps her selection.

A revert that cannot be honoured refuses and changes nothing. `restore_scene` checks the whole file against the registry and against its own set of props before it touches the world — `validate_checkpoint` does exactly this check — and when the file names a key this project has not declared, or a link to a prop the file itself does not contain, it raises `CheckpointError` and leaves the level byte for byte as it was, with `world_digest` unchanged. It raises nothing else, and it never refuses a file that does fit the level.

`restore_entity` refuses on the same terms, and it checks before it touches the prop. A designer keeps a per-prop checkpoint overnight and presses Revert on that prop alone the next morning, on a level other people have edited since, so the recorded state and the level it is offered to can disagree: when it names a key this project has not declared, or a tag carrying a payload, or a link to a prop that is not in the level any more, `restore_entity` raises `CheckpointError` and leaves that prop exactly as it was, `world_digest` unchanged. It raises nothing else — a prop that is no longer in the level is a `CheckpointError` too, not whatever the world happens to throw — and it never refuses a recorded state the level can take, including one whose links name props that are still there.

The change panel names exactly what differs under the editor's own comparison rule and nothing else. `compare_entities` returns `added`, `removed` and `changed` as sorted lists of trait and relation keys; `compare_scenes` returns the same three fields as sorted lists of prop ids. Both compare the canonical form of each side, which `canonical_snapshot` and `canonical_checkpoint` produce, so the order in which links were written down does not register as a change, and a prop with no `relations` key is the same as a prop with an empty one. Two files that mean the same level produce three empty lists.

`scene/checkpoint.py` and `scene/tools.py` are the files to change. `scene/protocol.py` ships in the editor's own release and the rest of the editor is built against it. You can inspect the project, replay the recorded sessions and run your own experiments before you deliver.
