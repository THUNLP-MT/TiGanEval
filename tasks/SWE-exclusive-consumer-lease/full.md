Complete the fleet job scheduler in `dispatch/assignment.py` so that a class of work that is one worker's job at a time stays one worker's job through everything this fleet does to it: replicas on separate links, a scheduler the supervisor rebuilds in place, a mixed-build rollout, every way a worker can lose a class, and the window each class allows. The shifts recorded under `project_records/` are four shifts this fleet has had, not the list of situations the finished scheduler has to handle. `dispatch/protocol.py` ships with the operator console and the worker agent; `dispatch/support.py` is yours.

While a class marked one worker's job at a time has a worker on it, every complete job the control plane supplied goes to that worker and to no other, exactly once, unchanged; the scheduler must neither invent another job nor alter its id, class or account. Which worker that is has to be decided when the job is handed over rather than when a claim was made, because the fleet changes between the two: a job must never reach a worker whose claim has been released, whose link has dropped, or whose class has been retired, and it must never reach two workers. A job put in while no worker has the class waits and goes to the next worker that takes the class, rather than being dropped. Calls made in this documented lifecycle, after their class has been declared, must not fail because of the scheduler's own bookkeeping.

The claims, the holders and the waiting work belong to the fleet, not to the link a worker happens to be on. The same workers making the same claims and the same jobs going in must produce the same fleet, and hand the same work to the same workers, whether they arrive over one link or over five; the fleet is many processes on many links, and that is the only shape it is ever in. Equally, a scheduler the supervisor has just rebuilt holds nothing from the process before it: no claim, no holder and no waiting job from an earlier scheduler may decide anything after a restart, and a class whose fresh worker is linked and claiming must not sit idle because of something the previous scheduler left behind.

Being one worker's job at a time is a property of the class, and once a class has it no later declaration takes it away. Every build declares the classes it runs at start-up through its own helper, and the fleet is mixed-build for as long as a rollout lasts, so a declaration that says nothing about it — from any worker, at any point — must not widen the class to a second worker and must not move the work off the worker already running it.

A worker only stops its own side of the partner connection when the fleet tells it that a class is no longer its, so every way a worker can lose a class it did not give up itself delivers exactly one notice to that worker, and the ways are all of them: its link dropping, the class being retired, and a higher-ranked worker taking the class from it. A worker that voluntarily releases its own claim already knows it is leaving and receives no revocation notice. A claim is that worker's side of the class whether or not it is the one running the class at the time, so a link that drops and a class that is retired take the class from every worker claiming it, the ones standing by included, and each of those workers is told. The notice reaches that worker as the class is taken away, or at the latest as the work moves on to whoever has it now. Exactly one per loss, including when the same worker regains the class and later loses it again, and only when the class really has been taken away — a worker whose claim is still live and still on the class hears nothing, because a worker told for nothing shuts down work it is still meant to be doing. What that worker's own code does when it hears is its business: a notice that raises must neither come back at the caller nor stop the fleet from finishing the removals behind it, which is what a link with several workers on it needs when one of them throws on the way out.

Rank decides who runs a class, and the window decides how much. On a class the fleet spreads across its workers, the highest-ranked worker that has room for the job takes it; when the top of the class is at its window the job goes to the next worker down rather than waiting, and it waits only when every worker on the class is full. On a class that is one worker's job at a time the two laws meet, and being one worker's job is the stronger of them: work beyond the window of the worker holding the class waits for that worker and goes nowhere else, however many other workers are standing by on the class. No worker ever holds more jobs of a class at once than that class's `max_in_flight`, counting a job from the moment it is handed over until the worker reports it done. Between workers the fleet has no reason to choose between, the one already running the class keeps it: a newcomer at the same rank as the worker holding the class does not take it, whatever order the claims arrived in.
